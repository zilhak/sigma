# `instance_resized_from_spec`

| | |
|---|---|
| 기본 | **OFF** (opt-in) |
| 스코프 | 스펙 컴포넌트의 INSTANCE |
| 추가 왕복 | **`get_nodes_info` 1회** (마스터 크기·스펙 alias resolve) |
| 자동수정 | 없음 |

## 무엇을 잡나

**작은 스펙 인스턴스를 배 이상 늘려 컨테이너 대용으로 쓴 것.**

## 왜 필요한가

[스펙 컴포넌트](../../component-spec.md)의 마스터는 HTML을 **고정 크기 자식 트리로 구운 것**이다.
인스턴스를 늘리면 **상자만 커지고 안쪽은 제자리에 남는다** — 오토레이아웃처럼 내용이 따라 늘지 않는다.

실제 사고: 16×16 체크박스를 48×42 표 칸으로 늘려 셀 대용으로 쓰다가, 선택 상태로 바꾸는 순간
체크박스의 배경이 상자 전체에 칠해져 **칸 전체가 색 덩어리**가 됐다. 늘려 쓰는 동안에는 멀쩡해 보여서
상태를 바꾸기 전까지 아무도 몰랐다.

## 파라미터

| 이름 | 기본값 | 설명 |
|---|---|---|
| `growthRatio` | **2** | 마스터 대비 이 배율 이상 커지면 위반 |
| `smallMaster` | **64px** | 이보다 큰 마스터는 대상 아님 — 원래 큰 요소를 늘린 건 의도로 본다 |
| `flagShrink` | **false** | 줄인 것도 잡을지 |
| `tolerance` | **0.5px** | 크기 비교 허용 오차 |

## 오탐과 의도적 스코프 축소

- ⚠️ **크기 차이 자체는 잡지 않는다.** 실측 결과 표는 열 너비 때문에 셀을 늘리고 줄이는 게 정상
  사용이라, 단순 크기 차이로 잡으면 **한 페이지에서만 2220건**이 나온다. 그래서 "작은 마스터를
  배 이상 키운 것"으로 범위를 좁혔다.
- **줄임은 기본 대상이 아니다.** 줄임의 실제 피해(자식 넘침)는 [`child_overflow`](child-overflow.md)가
  이미 잡는다. 원인 이름까지 듣고 싶을 때만 `flagShrink`를 켠다.

## 면제하는 법

[`lint-ignore`](../suppress.md)로 노드별 면제. 늘려 쓰는 게 정말 맞다면 그 크기의 스펙을 따로 등록하는
편이 낫다.
