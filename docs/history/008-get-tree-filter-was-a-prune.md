# 008. get_tree 의 `filter` 는 거르는 게 아니라 잘라내는 것이었다

> 관련 코드: `packages/figma-plugin/src/node-ops/tree.ts` (`matchesSelector`, `finalizeKeep`)
> 테스트: `packages/figma-plugin/__tests__/tree-filter-modes.test.ts`
> 2026-08-07 실측 · 2026-08-08 수정

## 증상

`filter` 는 이름만 "필터" 고 동작은 **화이트리스트 prune** 이었다 — 매칭하지 않는 노드를
**서브트리째** 잘라낸다. 그런데 도구 설명은 *"filter.types: 특정 타입만"* 이라고만 적혀 있었다.

그래서 가장 자연스러운 호출인 `filter.types:["TEXT"]` + `depth:"full"` 이 **오류도 경고도 없이
0건**을 돌려준다. TEXT 는 언제나 FRAME/INSTANCE 밑에 있는데 그 부모가 먼저 잘리기 때문이다.

### 실제로 부딪힌 사고

L2-2 페이지의 섹션 구조를 보려고 `get_tree(nodeId, depth:3)` 을 불렀더니 응답이 **59,989자**라
MCP 토큰 한도를 넘겨 파일로 떨어졌고, 그걸 python 으로 슬라이스해 읽는 왕복이 생겼다.
내용을 보니 자식 4개처럼 보이는 서브트리에 **SVG 임포트 산물 VECTOR 213개**가 들어 있었다.

그 213개는 전부 잎이라 잘라도 잃는 정보가 없었다. `filter` 로 해결되는 상황이었는데
**"특정 타입만 남긴다"로 읽히는 설명 때문에 아예 안 썼다.** 같은 세션에서 `filter` 를 한 번도
쓰지 않았다 — 개별 실수라기보다 **인자 의미가 뒤집혀 있어서**다.

그리고 설명을 정확히 이해했더라도 불편하다. "VECTOR 하나만 빼고 싶다" 인데 화이트리스트라
**남길 것을 전부 열거**해야 하고, 빠뜨린 타입이 하나 있으면 그 서브트리가 통째로 사라지는데
**응답만 봐서는 잘린 건지 원래 없는 건지 구분이 안 된다.**

## 무엇을 했나

의미가 하나씩인 인자 둘로 갈랐다. **`filter` 는 동작을 바꾸지 않고 그대로 뒀다**(기존 호출자).

| 모드 | 인자 | 동작 |
|---|---|---|
| 전체 | (없음) | 종전과 동일 |
| 자르기 | `omit` | 매칭 노드를 **서브트리째** 제외 (블랙리스트) |
| 남기기 | `keep` | 매칭 노드를 남기고 **조상은 뼈대만** 유지, 매칭 없는 가지는 제거 |

- 둘은 함께 쓸 수 있다(`omit` 먼저 → 남은 것에 `keep`).
- `filter` 와 `omit`/`keep` **동시 지정은 거부**한다. 조용히 한쪽을 무시하면
  "인자를 줬는데 아무 일도 안 일어남" 계열이 되므로 예외를 던진다.
- `filter` 설명을 *"매칭하지 않는 노드는 서브트리째 제외됩니다(prune)"* 로 정정했다.

## `keep` 의 limit/truncated 함정

`keep` 은 **뼈대 노드**를 만든다. 뼈대를 `nodeCount` 에 같이 세면 **뼈대가 limit 을 먹고
`truncated` 가 또 거짓말을 한다.** 그래서 limit/truncated 는 **매칭 노드 기준**으로만 세고,
뼈대는 `skeletonCount` 로 따로 돌려준다.

또 **`keep` 은 플러그인 순회 비용을 줄이지 않는다** — 전부 돌아야 매칭을 안다. 줄어드는 것은
전송량과 호출자 컨텍스트이고, 그게 병목이라 이득은 그대로다. 설명에 이 점을 적어 오해를 막았다.

## 테스트 함정 — 0건은 "안 돎"과 구분되지 않는다

`keep:{types:["TEXT"]}` 가 실제로 도는지 확인하려면 **반드시 걸리는 조건으로 먼저 1건 이상**
나오는지 봐야 한다(positive control). 0건은 "깨끗함"과 "안 돎"을 구분해 주지 않는다 —
[[004]], [[005]] 와 같은 원칙이다.

그리고 이 트리 픽스처는 `serializeTreeNode` 가 TEXT 의 `characters` 를 읽으므로 스텁에
그 필드가 없으면 검사 로직이 아니라 **직렬화에서 죽는다.** 실패 메시지가 규칙과 무관해 보이면
스텁부터 의심할 것.
