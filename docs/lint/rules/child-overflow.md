# `child_overflow`

| | |
|---|---|
| 기본 | **ON** (opt-out) |
| 스코프 | 모든 컨테이너 (서브트리 검사에서도 시작 노드가 컨테이너로 인식됨) |
| 추가 왕복 | 없음 |
| 자동수정 | **있음** — 컨테이너 확장(grow container) |

## 무엇을 잡나

트리상 자식이면 좌표상으로도 부모 안에 있어야 한다는 규약. 자식이 부모 **로컬박스(0,0~W,H)** 를
벗어나면 위반이다.

## 왜 필요한가

트리 구조와 시각적 위치가 어긋나면 사람이 보는 것과 도구가 아는 것이 달라진다. 부모를 옮기면 자식이
따라오는데, 화면에서는 자식이 다른 곳에 있는 것처럼 보이는 상태가 된다. `resize()`로 컨테이너를
줄이거나 자식을 늘렸을 때 흔히 발생한다.

**스펙 컴포넌트에서 특히 자주 터진다** — 루트에 `height`와 `border-width`를 같이 주면 내용상자는
그만큼 작은데 자식을 `height` 그대로 잡는 실수가 잦고, 그 실수가 **인스턴스마다** 위반으로 돌아온다
(표 셀 스펙 하나로 한 번에 250건이 난 적이 있다). 등록 시점에 잡으려고
[박스모델 경고](../../component-spec.md#등록-시-박스모델-경고-warnings)가 따로 있다.

## 좌표계

**모든 컨테이너가 자식 로컬좌표를 쓴다** — SECTION도 자식 원점을 새로 잡는다. 따라서 판정은 항상
"부모 로컬박스 0,0~W,H 안인가"다. `sigma_get_tree`의 `boundingBox`가 이 로컬좌표이므로 수정도 그 값으로
한다(다른 컨테이너에 든 노드끼리 비교할 땐 `absolute`를 써야 한다).

## 파라미터

없음. `{ "enabled": false }`로 끄는 것만 가능하다.

## 오탐과 의도적 스코프 축소

- **배치형 노드만, 리프 제외.** 텍스트 같은 리프는 렌더 박스가 실제와 달라 오탐이 난다.
- **GROUP은 컨테이너로 보지 않는다.** GROUP의 바운딩박스는 자식들의 합집합이라 정의상 자식이 밖에
  나갈 수 없다 — 컨테이너로 취급하면 무의미한 판정이 된다.
- **[기획 레이어](../annotation-layer.md)는 면제**(`annotation_layer` 규칙을 켠 경우).

## 자동수정

`sigma_lint({ apply: true })`로 **부모를 키워** 자식을 품게 한다. 자식을 옮기지 않는다 — 어디로
옮길지는 사람 판단이기 때문이다.

⚠️ 컨테이너를 키우면 형제를 덮을 수 있으므로, 적용 후 [`section_overlap`](section-overlap.md) ·
[`card_overlap`](card-overlap.md) 회귀 검사가 함께 돈다(`apply` 응답의 `after`).

## 면제하는 법

[`lint-ignore`](../suppress.md)로 노드별 면제.
