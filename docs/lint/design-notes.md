# 설계 원칙 · 데이터 갭

## 설계 원칙 / 근거

1. **표현력은 기존 언어에서 빌리고 새 언어는 최소화** — 컴포넌트 스펙이 HTML/CSS를 택한 이유와
   동일(에이전트가 이미 유창해 학습비용 0). JSON 연산자를 5개로 못박은 것도 같은 이유 —
   관계형/유도값 검사까지 JSON으로 밀면 결국 축소판 언어를 재발명하게 된다.
2. **빌트인=선언적 옵션, 확장=코드형 함수** — ESLint/Stylelint 둘 다 이 이분법을 쓴다는 벤치마킹
   근거. 순수 JSON DSL만으로 임의 확장 규칙을 표현한 성공 사례가 없었다.
3. **실행은 항상 서버** — Figma 플러그인은 QuickJS(WASM) 샌드박스이고 Figma가 애초에 동적 코드를
   호스트에서 격리하려 도입한 것이라, 서버→플러그인으로 규칙 코드를 실어 날라 그 안에서
   실행시키는 건 Figma의 보안 모델과 충돌한다. 또한 무한루프가 나면 사용자의 실제 Figma Desktop
   세션이 멈춘다(서버 프로세스가 멈추는 것보다 피해가 훨씬 큼).
4. **오탐 방지가 검출률보다 우선** — 규칙이 오탐을 내면 사람은 규칙을 끄지, 문서를 고치지 않는다.
   여러 룰의 "의도적 스코프 축소"(비사각형 제외, 컨테이너 후보 제외, 크기 차이 자체는 안 잡음 등)가
   전부 이 원칙에서 나왔다. 각 룰 문서의 §오탐과 의도적 스코프 축소 참조.
5. **조용한 false-clean 금지** — 부분 스캔·판정 불가·플러그인 구버전 같은 상황에서 "위반 없음"으로
   보고하지 않는다. `scanTruncated`/`scopeContainerUnknown` 같은 플래그로 왜 못 봤는지를 드러내고
   `clean`을 false로 만든다.

## 데이터 갭 (아직 지원 안 함)

- **변수 바인딩(`boundVariables`)**: 색상/패딩/radius가 Figma 변수에 바인딩됐는지 검사하는 규칙은
  아직 못 만든다 — `packages/figma-plugin/src/node-ops/query.ts`가 이 필드를 안 읽는다. 노출되면
  `ctx.resolveVariableName` 같은 헬퍼 추가 가능.
- **WCAG 명도 대비**: 계산 공식 자체는 고정이라 빌트인 후보이지만, "실효 배경색"을 구하려면 조상을
  올라가며 첫 SOLID fill을 합성하는 별도 유틸이 선행돼야 한다.

## 엔진 소스

- `packages/shared/src/lint/` — 규칙 실행, 순수 함수, 유닛테스트
- `packages/server/src/lint/` — config 로드/해석, enrich, predicate worker 실행, 리포트
